# カードテスト / BIN アタック調査ナレッジ（INCIDENT_CASE）

本メモは公開研究と一般的な不正対策実務に基づく PoC 用の内部ナレッジであり、
PCI-DSS 本文の複製ではない。

## 典型パターン

1. 短時間に少額（例: 0.50〜5 USD）を連続オーソリし、有効カードを選別するカードテスト。
2. 同一 BIN（カード番号先頭6桁に相当するクラスタ）から Amount を段階的に上げる。
3. 失敗オーソリのあと成功オーソリが続く場合、ボットによるリスト攻撃の可能性。

## credit_detect での近似観測

公開データセットに BIN 列は無い。代理指標として次を見る。

- Hour が深夜帯に集中
- Amount の二極化（極少額と高額）
- V14/V17 が正常群から KS >= 0.40 で分離
- `fraud_probability` 上位 0.1% の Capture Rate

## 是正の方向

少額連続を遮断し、高スコアかつ Amount>=200 は 3-D Secure / マニュアルレビューへ回す。
恒久対応は Dataform のフィルター SQLX として提案する（本 PoC では SQL 提案まで）。
